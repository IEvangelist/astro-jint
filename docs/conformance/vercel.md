## Differences

- **Build output.** Upstream reads `.vercel/output` (`config.json` routes, `functions/*.func/.vc-config.json`, `static/`). This adapter writes `astro-jint.json` (the routes with their `prerender` flag, `staticHeaders`), `client/` (the files that are served: prerendered pages, `_astro/`, the sitemap, `404.html`) and `server/entry.mjs` with its chunks. The tests assert the HTTP behaviour each snapshot is meant to produce and, where it is a fact about the build, the manifest or the files (for example `client/index.html`, the route of the manifest in `HasRoute`).
- **Route-table order.** Vercel answers redirects, then the immutable-cache rule of the assets folder, then the CSP headers of prerendered pages, then the filesystem, then the function, then the 404 catch-all. The host answers static files first (hashed files of the assets folder with `Cache-Control: public, max-age=31536000, immutable`, other files with an ETag and `public, must-revalidate, max-age=0`, the recorded CSP of prerendered pages), then renders everything else in Jint: Astro's redirects, on-demand routes and the 404 page. Classes: `RedirectsTests`, `StaticAssetsTests`, `StaticHeadersTests`, `StaticTests`, `PrerenderedErrorPagesTests`, `ServerRenderedErrorPagesTests`.
- **Redirects are answered at run time.** The adapter builds with `build.redirects: false`, so no redirect has a file and Astro answers them in the app, after its own trailing-slash redirect. With `trailingSlash: 'always'` `/one` goes to `/one/` first and only then to its destination, where Vercel answers in one step; `RedirectsTests` follows the chain and compares the last redirect (`Location` with the trailing slash that the setting asks for). The position of the assets cache rule between the redirects and the files is seen as: a hashed file of the assets folder is immutable, a redirect whose source is in that folder (`/_astro/legacy.css`) is not.
- **No ISR, no path override.** `x_astro_path`, `x_astro_path_token`, `x-astro-path`, `x-vercel-isr`, `x-astro-locals` and `x-astro-middleware-secret` mean nothing to the host; `PathOverrideSecurityTests`, `IsrTests` and `IsrEdgeMiddlewareTests` show that none of them steers the route. In `vercel-server` `/_isr` is answered by the `[id]` page (the upstream fixture has no such route and answers 404), in the static builds it is a 404.
- **Middleware and cache keys.** Astro's middleware runs inside the app: after the redirects, for on-demand routes only (pages, endpoints, the 404 page and the paths that no route matches), never for static files. What the ISR route table does with the cache key shows up as: every path renders with its own parameters, and the query string reaches the endpoint. `vercel-server`'s middleware sets the cookie `foo=bar`, has a top-level await and sets `x-astro-middleware: ran` and `x-message` after `next()`.
- **Images.** The adapter keeps Astro's local image service with a pass-through transform (the host has no `sharp`): `/_image` serves the file as it is, with its own type, whatever width and format are asked for (`HostedTests` asks for `w=300&f=webp`), and the images of prerendered pages are hashed files of `_astro/`. The list of sizes of Vercel's service is not reproduced, so the srcset test (`ImageTests`) checks properties: ascending unique widths, each descriptor equal to the `w` of its URL, every URL a served image.
- **Static builds ship the server entry.** `server/entry.mjs` exists for `output: 'static'` too (redirects, server islands and sessions are answered at run time), so `StaticTests` asserts that prerendered pages are served from the files, with the validators of a static file, instead of asserting that there is no function.
- **Fixtures.** The 24 upstream fixtures are consolidated into two: `vercel-server` (`output: 'server'`, `jint({ staticHeaders: true })`, sitemap, a redirect, `security.csp`, middleware) and `vercel-static` (`output: 'static'`, sitemap, the redirects of the redirects test). Config variants cover a prerendered 404 page, `build.assets: '_foo'` and `trailingSlash: 'always'`. Adapter options are fixed per fixture, and those of upstream with no counterpart (`isr`, `edgeMiddleware` / `middlewareMode`, `imageService`, `webAnalytics`, `maxDuration`, `streaming`, `includeFiles`) are not set; the pages and endpoints that the ported tests need come from the upstream fixtures and are in `vercel-server` (on demand) and `vercel-static` (prerendered).

## Gaps

- **GAP-VERCEL-1**: a redirect to another site does not keep the status of its configuration. With `redirects: { '/four': { status: 302, destination: 'http://example.com' } }` the host answers `301` with `Location: http://example.com/`; upstream (and the config) say `302`. Skipped test: the case `/four` of the theory "define static routes" in `RedirectsTests` (`ExternalStatusGap`). Suspected area: Astro core, `computeRedirectStatus` ignores the configured status when there is no `redirectRoute`; Vercel does not run that code because the adapter turns the redirects into routes of `config.json`. Reproduce: remove the `Skip` of the `/four` case and run `dotnet test --project tests/AstroJint.Conformance.Tests/AstroJint.Conformance.Tests.csproj -- --filter-class AstroJint.Conformance.Vercel.RedirectsTests`, or `GET /four` on `vercel-static` (status 301 instead of 302). The cases `/one`, `/two` and `/three` pass.
- **GAP-VERCEL-2**: with `trailingSlash: 'always'`, a redirect whose source is a file name (`/Basic/http-2-0.html` to `/posts/http2`) is not found without the trailing slash: `GET /Basic/http-2-0.html` answers `404` (Astro's trailing-slash redirect does not apply to a path that looks like a file, and the redirect route only matches `/Basic/http-2-0.html/`). Skipped test: "define redirects for static files" in `RedirectsTests`. Suspected area: Astro core, trailing-slash handling and redirect route matching at run time; again, Vercel's route table matches the source regardless. Reproduce: remove the `Skip` and run the class as above, or `GET /Basic/http-2-0.html` on `vercel-static` with the `trailingSlash: 'always'` variant (the same request with the slash, and without the setting, redirects correctly; both are covered by passing tests). A fix would be a host or adapter redirect table from the manifest, answered before the app; it is the lead's decision.

## Not applicable

- **Vercel function and platform configuration (no HTTP counterpart in this host):** `max-duration` (`maxDuration` in `.vc-config.json`), `streaming` (`supportsResponseStreaming`), `web-analytics` (script injected by the Vercel Web Analytics product), the `images` section of `config.json` and the sizes of the Vercel image service (`image.test.ts`: "generates valid image sizes when requested width is larger than source image", "generates valid densities-based srcset using only configured sizes", "has proper vercel config").
- **Vercel Build Output API, ISR and edge functions:** `edge-middleware.test.ts` ("an edge function is created", "deployment config points to the middleware edge function", and the two `it.skip` tests "with/without edge handle file, should successfully build the middleware", which look for `middleware.mjs` inside `render.func`); `isr.test.ts` ("generates expected prerender config", "allow-lists every query param used in the ISR rewrite", "uses $1 (not $0) in ISR route dest", "captures the full pathname as group 1 of every emitted ISR pattern"); `isr-edge-middleware.test.ts` ("builds the middleware edge function", "leaves internal endpoints on the serverless function", "keeps the ISR config", "forwards cached routes to the ISR function", "forwards endpoints to the ISR function too", "routes straight to the ISR function", "wraps spread-route patterns in the capture group $1 references", "captures the full pathname as group 1 of the emitted root and spread patterns", "builds no middleware function"). What these routes are meant to do is covered by the adapted tests of the same files.
- **File tracing and function packaging (`@vercel/nft`):** `serverless-prerender.test.ts` ("outDir is tree-shaken if not needed", `it.skip('includeFiles work')`), `outdir-outside-root.test.ts` (`.vercel/output/config.json` and traced chunks of the function), `units/nft.test.ts` (`findCommonAncestor`). The harness cannot build with an `outDir` outside the fixture root (`FixtureBuilder` and `variant.mjs` force a `dist*` folder inside it). A one-off `astro build` of `vercel-static` with the output outside the root (`CONFORMANCE_OUT_DIR=../../../../outdir-probe-dist`) produced a complete output (`client/index.html`, `server/` with 3 modules, `astro-jint.json`); that probe is not automated.
- **Vercel-only modules:** `cache-provider.test.js` (the opt-in provider `@astrojs/vercel/cache` with the proprietary headers `Vercel-CDN-Cache-Control` and `Vercel-Cache-Tag`), `units/middleware.test.ts` (`generateEdgeMiddleware`, the hint of the edge bundler when a middleware imports a Node.js built-in).
- **Build-time validation by `@vercel/routing-utils`:** `redirects.test.ts` "throws an error for invalid redirects". The build of this adapter does not convert redirects into Vercel routes, and Astro accepts that source.
